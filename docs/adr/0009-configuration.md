# ADR 0009 — Configuration and secrets

Status: Accepted — 2026-10-24

## Context

oroshi is deployed only through its NixOS module. The configuration contract is one TOML file generated by Nix, a serde struct, no secret inside, no environment variables.

## Decision

- One **TOML file generated by the NixOS module**, passed with `--config <path>`. Its schema is one Rust struct (serde, `deny_unknown_fields` everywhere); typed module options mirror its fields one to one (0012), including `storage.gcTargetRatio` for `storage.gc_target_ratio`. Exceptions: module-only `enable`, `package`, `persistPaths` and `gc.schedule` have no TOML field; `settings` is the raw TOML escape hatch, merged last and still validated by `config check`. `listen` maps to `server.listen`, `stateDir` to `storage.dir`; other names use camelCase for snake_case fields. Safe defaults in the code; the module writes only what differs.
- Sections (O1): `[server] listen`, `[metrics] listen` (absent = no listener), `[log] level, access`, `[storage] dir, max_bytes, gc_target_ratio`, `[gc] orphan_grace`, `[retention] days`, `[tokens.<name>] sha256, scopes`, `[nix] priority, trusted_keys, max_nar_bytes`. Each later module adds its own table.
- **No secret in the file**: token entries are hashes (0008), Nix keys are public (0007). If a module ever needs a secret (an upstream credential), it is a `*_file` path to a deployment-provisioned secret file, owned by the `oroshi` user, mode 0400, read at startup.
- `oroshi config check --config <path>` validates without starting (unknown key, malformed hash, `metrics.listen` not on loopback, unknown scope); the module runs it at build time on the generated file.
- No configuration through environment variables except `RUST_LOG` (verbosity) and systemd's own (`NOTIFY_SOCKET`).
- A configuration change restarts the service (`restartTriggers`); no hot reload.

## Consequences

- A unit test deserializes the complete example configuration; a module-evaluation check proves the generated file passes `config check`.
- The configuration is versioned in the deployment repository and reproducible.

## Rejected alternatives

- Hot reload on SIGHUP: tokens and keys change rarely and a restart takes milliseconds; an interrupted `nix copy` is run again and skips the paths already present.
- CLI flags or environment variables: unreadable in a module, and secrets leak to `ps` and logs.
